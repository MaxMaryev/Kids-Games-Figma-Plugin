# 😊 Kids Games Plugin 😊

Плагин для [Figma](https://www.figma.com/) с четырьмя инструментами для подготовки игровой графики:

1. **Растр** — превращает выделенный слой или группу в PNG прямо на канвасе. Появляется прямоугольник с картинкой-заливкой — удобно, когда нужно «зафиксировать» вектор и работать с ним как с готовым ассетом, не выходя из файла.
2. **Кратность 4** — проверяет, что ширина и высота слоя кратны четырём (важно для текстурных атласов, сжатия и платформенных требований). Если кратности нет, плагин аккуратно оборачивает слой фреймом нужного размера. Сама графика при этом не растягивается.
3. **Ренейминг** — переименовывает выделение по шаблону из списка типов (`Eyes_`, `Hair_Front_`, `T-shirt_`…) сверху вниз, как в панели Layers, с нумерацией всегда от `01`. Список типов правится прямо в плагине.
4. **PSD** — собирает из выделенного фрейма файл `.psd`: каждый слой Figma становится слоем Photoshop, вложенность в группах и имена сохраняются.

## Установка (для художников)

Собирать ничего не нужно — `code.js` уже лежит в репозитории готовым.

1. Скачайте папку плагина (**Code** → **Download ZIP** на GitHub) и распакуйте её в удобное место. Эта папка должна остаться на диске — Figma читает плагин прямо из неё.
2. В десктопной Figma: **Plugins** → **Development** → **Import plugin from manifest…**.
3. Укажите `manifest.json` из папки плагина.
4. Запуск: **Plugins** → **Development** → **😊 Kids Games Plugin 😊**.

Нужна именно [десктопная Figma](https://www.figma.com/downloads/) — в браузерной версии пункта **Development** нет.

## Обновление

Когда выходит новая версия, плагин показывает баннер. Порядок такой:

1. Закройте плагин в Figma.
2. В папке плагина запустите `UPDATE.bat` — он скачает свежую версию с GitHub и заменит файлы.
3. Откройте плагин заново. Внизу окна должна стоять новая версия — это и есть проверка, что всё получилось.

Нужны Node.js, `curl` и `tar` (последние два есть в Windows 10+ из коробки). Переимпортировать плагин в Figma не нужно — путь к папке не меняется.

## Разработка

```bash
npm install
npm run build
```

Скрипт [`build.cjs`](build.cjs) собирает [`src/main.ts`](src/main.ts) в `code.js` и встраивает [`ui.html`](ui.html) в плейсхолдер `__html__` (как ожидает [`manifest.json`](manifest.json)). Версия из `package.json` попадает в `code.js` как `__PLUGIN_VERSION__` — её показывает подвал окна и по ней работает баннер обновления.

Сборка идёт **в два прохода**. Сам `ui.html` через сборщик не проходит, а вкладке PSD нужна библиотека `ag-psd`, поэтому первым проходом [`src/ui/psdExport.ts`](src/ui/psdExport.ts) собирается в IIFE и вставляется в `ui.html` на место маркера `/* __KGP_PSD_BUNDLE__ */`, и только потом всё это уезжает в `code.js`. Отсюда и размер `code.js` — около 460 КБ вместо прежних 145 КБ.

Проверка типов — два конфига, потому что песочнице DOM не нужен и давать его туда нельзя:

```bash
npm run typecheck
```

Перед `npm run verify` нужен **`npm ci`**, а не `npm install`: `verify.cjs` сравнивает `code.js` побайтово, и другая патч-версия `ag-psd` честно уронит проверку.

Пересборка при изменениях:

```bash
npm run watch
```

Подробности по полям манифеста — в [документации Figma Plugin API](https://developers.figma.com/docs/plugins/manifest).

## Релиз

`code.js` — не артефакт сборки, а то, что раздаётся пользователям: `UPDATE.bat` просто копирует файлы из репозитория, ничего не собирая. Поэтому `code.js` **лежит в git** и должен быть пересобран перед релизным коммитом.

1. Поднимите `version` в `package.json`.
2. `npm run release` — соберёт и проверит, что версия внутри `code.js` совпадает с `package.json` (иначе упадёт).
3. Закоммитьте вместе с `code.js` и запушьте в `main`.

Баннер обновления сравнивает версию, зашитую в `code.js`, с `version` из `package.json` на ветке `main` — до пуша никто ничего не увидит.

## Вкладка «Растр»

1. Выделите один или несколько слоёв.
2. Выберите масштаб (1×–4×) — тот же множитель, что и при обычном экспорте PNG.
3. По желанию поставьте галочку:
   - **Заменить оригинал** — исходный слой удаляется, остаётся только растр.
   - **Скрыть оригинал** — исходный слой остаётся, но становится невидимым.
4. Нажмите **В растр**.

На месте оригинала появляется прямоугольник с PNG-заливкой; выделение переходит на новые растры — их сразу можно подвинуть или проверить. Если родитель с auto layout, растр позиционируется абсолютно, чтобы встать ровно туда, где был оригинал, и не сдвинуть соседей в ряду.

## Вкладка «Кратность 4»

Два действия — **Проверить** и **Поправить**.

### Проверить

Смотрит на размеры с учётом теней, обводок и размытий — то есть на то, сколько места слой реально занимает на экране. Размеры округляются вверх до целых пикселей, потом проверяется кратность 4.

В выделении остаются только нарушители; в списке внизу появляются их имена, текущие размеры и до чего нужно дотянуть. Клик по строке (или по «Показать») переводит фокус Figma на слой.

### Поправить

Создаёт фрейм-обёртку вокруг слоя:

- Обёртка получает имя исходного слоя — в дереве слоёв «контейнер» выглядит знакомо.
- Сам слой переезжает внутрь и переименовывается в **`[no4] <старое имя>`** — так видно, какие слои изначально не проходили проверку.
- Размер обёртки увеличивается до ближайшего сверху кратного 4 по каждой стороне (не больше +3 пикселей). Графика внутри не растягивается: меняется только контейнер, содержимое смещается так, чтобы визуально остаться на месте.
- После операции в выделении — сами обёртки.

Чего **Поправить** не делает:

- Не трогает слои, у которых размеры уже кратны 4.
- Не оборачивает в саму страницу/документ или в главный компонент — это могло бы поломать инстансы.
- В редких случаях, когда слой сильно обрезается родителем, проверка может разойтись с фактическим PNG при экспорте. Это компромисс между точностью и скоростью; на типичных ассетах не проявляется.

## Вкладка «PSD»

1. Выделите **один** фрейм (подойдут также компонент, инстанс, секция и группа).
2. Выберите масштаб (1×–4×) — он умножает и размер холста, и все слои.
3. Нажмите **Собрать PSD**. Файл скачается браузером под именем фрейма.

Что получается в Photoshop:

- Фрейм, группа, компонент и инстанс становятся **папкой**; всё остальное — обычным слоем с картинкой.
- Имена сохраняются как есть, кириллица в том числе.
- **Размер каждого слоя сохраняется**: рамка слоя в Photoshop совпадает с боксом слоя в Figma, с учётом теней, размытий и обводок. У папок собственных габаритов в PSD нет в принципе — Photoshop считает их по содержимому.
- Содержимое клипующих фреймов обрезается ровно так же, как на канвасе.
- Сплошная заливка корневого фрейма приезжает нижним слоем **Фон** — его можно выключить и получить прозрачный документ.

Чего PSD-экспорт **не** делает:

- Текст растрируется. Редактируемых текстовых слоёв в PSD не будет.
- Прозрачность и режимы наложения **запекаются в пиксели**: у слоя в Photoshop всегда Opacity 100 % и режим Normal. Выглядит один в один, но покрутить прозрачность отдельно уже нельзя.
- Скрытые слои не переносятся вовсе, видимость в документе плагин не трогает.
- Группа с маской приезжает одним готовым слоем — живой маски в PSD не будет.
- Фрейм с собственной заливкой, обводкой, эффектом, прозрачностью или режимом наложения тоже схлопывается в один слой: иначе картинка разъехалась бы. Обычные группы Figma этого не касается — они остаются папками.
- Повёрнутый фрейм экспортировать нельзя: холст PSD не бывает повёрнутым. Повёрнутые слои **внутри** — нормально.
- Полупрозрачные пиксели могут разойтись с оригиналом на 1/255 по каналу: браузер премультиплицирует альфу при декодировании. На глаз незаметно.
- Потолки: до 800 слоёв и до ~1,2 ГБ пикселей за раз. Сторона больше 30000 px автоматически переключает файл в `.psb`.

Замечания по ходу экспорта (что схлопнулось и почему) плагин показывает списком под прогрессом.

## Ограничения

- Нужно явное выделение — без него плагин напомнит выбрать слой.
- Для растра у слоя должны быть валидные границы.
- Все операции над файлом локальные. В сеть плагин ходит только за одним — читает `package.json` с `raw.githubusercontent.com`, чтобы узнать, не вышла ли новая версия (см. `networkAccess` в [`manifest.json`](manifest.json)).

## Стек

- TypeScript, сборка [esbuild](https://esbuild.github.io/), типы [`@figma/plugin-typings`](https://www.figma.com/plugin-docs/).
- Запись `.psd` — [`ag-psd`](https://github.com/Agamnentzar/ag-psd) (лицензия MIT), единственная рантайм-зависимость; едет к пользователям внутри `code.js`.

## Структура исходников

- [`src/main.ts`](src/main.ts) — `showUI`, маршрутизация сообщений.
- [`src/features/rasterize.ts`](src/features/rasterize.ts) — растрирование.
- [`src/features/multipleOfFourCheck.ts`](src/features/multipleOfFourCheck.ts) / [`multipleOfFourFix.ts`](src/features/multipleOfFourFix.ts) — Проверить / Поправить.
- [`src/domain/multipleOfFour.ts`](src/domain/multipleOfFour.ts) — чистая математика кратности и отступов.
- [`src/features/renameLayers.ts`](src/features/renameLayers.ts) — Ренейминг.
- [`src/domain/layerNamePresets.ts`](src/domain/layerNamePresets.ts) — стандартный список типов и правила имени.
- [`src/domain/presetTreeOps.ts`](src/domain/presetTreeOps.ts) — правка списка типов (чистые операции над деревом).
- [`src/figma/geometry.ts`](src/figma/geometry.ts), [`nodeQueries.ts`](src/figma/nodeQueries.ts) — геометрия и запросы к узлам.
- [`src/features/psdExport.ts`](src/features/psdExport.ts) — экспорт в PSD со стороны песочницы: сессия, лимиты, выдача PNG-байтов слой за слоем.
- [`src/figma/psdTraversal.ts`](src/figma/psdTraversal.ts) — правила обхода: что становится папкой, что схлопывается, что пропускается.
- [`src/domain/psdLayout.ts`](src/domain/psdLayout.ts), [`psdFileName.ts`](src/domain/psdFileName.ts) — координаты слоёв и имя файла (чистые, общие для песочницы и UI).
- [`src/ui/psdExport.ts`](src/ui/psdExport.ts) — сборка файла в iframe: декодирование PNG, `ag-psd`, скачивание. Собирается отдельным проходом и вставляется в `ui.html`.

Обновление у пользователя: [`UPDATE.bat`](UPDATE.bat) → [`update-plugin.cjs`](update-plugin.cjs) (скачивание zip, проверка полноты архива, копирование). Релизная сборка — [`release.cjs`](release.cjs).
